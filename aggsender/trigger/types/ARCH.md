# ARCH: aggsender/trigger/types

## Overview

A single Go file defines two value types (`EpochEvent`, `EpochStatus`) and one interface (`EpochNotifier`). The value types are plain structs with `String()` methods for logging; the interface is the abstraction every concrete notifier in the sibling `aggsender/trigger` package implements, and that downstream subscribers (the epoch-based trigger) consume. The generated `mocks/` subdirectory mirrors `EpochNotifier` for unit tests in the sibling package.

`EpochEvent.ExtraInfo` is typed as `fmt.Stringer` so each notifier implementation can attach its own diagnostics (block numbers, timestamps, slot offsets) without this package depending on them. Upholds SPEC #2.

`EpochStatus.String()` multiplies `PercentEpoch` by the unexported constant `perCent = 100.0` and formats with `%.2f%%`, producing outputs like `EpochStatus: [1, 52.14%]`. Upholds SPEC #4.

## Patterns

- **1.** New fields added to `EpochEvent` or `EpochStatus` SHOULD remain plain data (no methods beyond `String()`); logic belongs in notifier implementations, not in these value types.
- **2.** New methods on `EpochNotifier` SHOULD be added here (not on a concrete type) so every implementation and its generated mock stay in sync.

## Notable decisions

- **3.** `ExtraInfo` is `fmt.Stringer` rather than a concrete struct or `any`. A concrete struct would force this package to know about block-based, time-based, and future epoch sources; `any` would lose the guarantee that the field is always loggable. `fmt.Stringer` gives implementations freedom while preserving SPEC #2.
- **4.** `Start(ctx context.Context)` returns no error. Start-time failures are expected to be surfaced via the caller's context or via construction-time validation in the factory; the interface deliberately keeps the runtime shape simple so it can be driven from a goroutine without error plumbing.
- **5.** The `mocks/` subdirectory is generated by mockery from this interface and is intentionally undocumented — the source of truth is the interface above, and regenerating the mock must not look like a contract change.
