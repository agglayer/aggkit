## Overview

The package is a flat set of Go files, each covering one concern. `interfaces.go` declares the abstractions that the rest of `aggsender/` implements and consumes; `types.go` holds the core certificate and mode value types with their string/DB adaptors; `certificate_build_params.go` holds the pre-/build-parameter structs plus size/retry/filter helpers that `flows/` relies on; `multisig_committee.go` encapsulates the committee invariants behind a constructor; `fep_inputs.go` defines the two hash pre-images used for aggchain-proof public values; `aggchain_proof_client_interface.go` defines the request/response shape for the aggchain-proof client; `status.go` defines the liveness surface exposed over RPC/health endpoints; `block_range_adjustment.go` and `optimistic_interface.go` are small option/interface carriers.

Each SPEC claim is upheld in exactly one place: modes and kinds in `types.go` (upholds SPEC #1–#6, #28–#29, #32–#33); committee in `multisig_committee.go` (upholds SPEC #7–#12, #30); build params in `certificate_build_params.go` (upholds SPEC #13–#20, #31); hash encodings in `fep_inputs.go` (upholds SPEC #21–#23); settled-blocks helpers in `types.go` (upholds SPEC #24–#27). `interfaces.go` holds only declarations — it defines the seams but does not enforce claims on its own.

## Patterns

- **1.** New sum-typed enumerations SHOULD follow the pattern used by `AggsenderMode` / `CertificateType`: a named string or uint8 type, a small set of exported constants, a `String()` method, a `NewXFromStr` (or equivalent) constructor that returns a typed error on unknown input, and `database/sql/driver.Value`/`Scan` methods when the value is persisted via `meddler`. Skipping any of these breaks the round-trip guarantees in SPEC #28–#29.
- **2.** New `String()` methods on pointer receivers SHOULD nil-check the receiver and fall back to the `NilStr` constant. This is a package-wide convention so that formatted log lines never panic on optional fields (`Certificate.AggchainProof`, `CertificateHeader.PreviousLocalExitRoot`, etc.).
- **3.** New abstractions that span subsystems SHOULD be declared as an interface in `interfaces.go` (or a dedicated `*_interface.go` file when the interface needs types that would bloat `interfaces.go`), not embedded as concrete types on the consumer side. The existing split (`interfaces.go` for the common flow/querier set; `aggchain_proof_client_interface.go` and `optimistic_interface.go` for narrower client-style seams) should be preserved rather than merged.
- **4.** New value types that cross the DB boundary SHOULD carry `meddler` tags and SHOULD keep tag names stable; renames are a storage-format break and require a migration in `aggsender/db`.
- **5.** Helpers on value types SHOULD tolerate a nil receiver when they are reasonably called on optional fields; see `CertificateBuildParams.NumberOfBridges`, `NumberOfClaims`, `NumberOfBlocks`, `MaxDepositCount`, and `CertificateHeader.ID`/`IsClosed`/`ElapsedTimeSinceCreation` for the existing precedent.

## Notable decisions

- **6.** `AggregationProofPublicValues.Hash` uses SHA-256 over ABI-encoded (non-packed) arguments, while `AggchainParams.Hash` uses Keccak-256 over a hand-rolled packed encoding. The two hashes are not interchangeable and both are consumed by on-chain/off-chain verifiers; do not "unify" them into a single `abi.Pack` + `keccak` without changing every verifier that agreed on the current encoding. The `AggregationVKeyHash` field is deliberately omitted from the `AggregationProofPublicValues` pre-image; this matches the verifier and SPEC #21.
- **7.** `AggchainParams.Hash` encodes `L2BlockNumber` as a left-padded 32-byte big-endian `uint256` (not the native `uint64` bytes) — the Solidity verifier treats it as `uint256`. Changing the padding width silently breaks the off-chain/on-chain hash agreement.
- **8.** `MultisigCommittee.signers` is kept both as a slice (for deterministic iteration order matching the on-chain signer order) and as a set (for O(1) membership). `Signers()` returns a deep-copied slice of values rather than the internal pointer slice, so external callers cannot mutate committee state. A refactor that exposed the internal slice directly would break SPEC #12.
- **9.** `CertificateBuildParams.GetClaimsFilteringUnclaims` allocates a fresh slice and uses a linear scan with a `usedUnclaims` bitmap so a single unclaim matches at most one claim. The comment notes that `Unclaims` is empty 99.9% of the time; the short-circuit returning a copy in that case exists so callers can mutate the returned slice without aliasing the input. Changing the filter to a map-based join would also be acceptable so long as the one-to-one rule (SPEC #17) and the fresh-slice contract (SPEC #19) hold.
- **10.** `CertificateType` uses `0` as `Unknown` and also as the zero value of the Go type. `NewCertificateTypeFromStr("")` deliberately returns `(CertificateTypeUnknown, nil)` so that default/zero values deserialise without error — any change here must keep that behaviour or update every call site that persists optional cert types.
- **11.** `SettledBlocks.EarliestBlock` excludes two fields from the minimum under specific conditions (IBE absent; L2 settled block == 0). These exclusions exist because those fields are semantically "not present" rather than "block zero"; collapsing the distinction would incorrectly drive the minimum to 0 on PP-mode networks and on networks with no settled IBE. The helper returns the first source error on any failure and does not attempt a partial minimum — this is intentional so callers cannot mistake a partial result for a complete one.
- **12.** `HealthCheckStatus` is a type alias (`= string`) rather than a distinct named type. This keeps it trivially JSON-serialisable as a plain string and avoids forcing every caller to import this package just to name a status; the trade-off is that arbitrary strings compile, so the `HealthCheckStatusOK` constant is the single source of truth for the "healthy" value (SPEC #6).

## Dependencies

- `github.com/agglayer/aggkit/agglayer/types` — source of `Certificate`, `CertificateHeader`, `Multisig`, the size constants used by `EstimatedSize`, and the settled-IBE shape. This is the closest dependency and the shape of this package follows it; changes on that side often require matching additions here.
- `github.com/ethereum/go-ethereum/accounts/abi` and `crypto` — used only by `fep_inputs.go` for the two hash implementations; no other file should reach for ABI encoding or keccak directly.
- `meddler` struct tags (no direct import) — consumed by `aggsender/db`; the tag strings are part of the contract.
